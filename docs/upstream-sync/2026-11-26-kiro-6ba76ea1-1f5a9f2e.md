## 保留的本地行为和单独决策

- OAuth 导入与刷新专用代码在 nianzs 固定范围内没有实质变化。现有本地 External IdP、组织登录、区域选择和机器 ID 继续沿用。IDE 导入仍需明确来源，现有 Social 刷新接口允许留空具体来源。
- `ddc28be64` 的相容入口换号传播和 `3b066a1c9` 的 WebSearch 终态已有本地等价实现。WebSearch 的缓存计量上下文仍适合单独对齐。
- 账号 ID 稳定的缓存命名空间可独立改善续期后的命中。Redis 共享缓存、默认补缓存断点、按 credits 反推用量、API Key 和会话隔离、直连 `count_tokens` 改为 404，均涉及计费、状态存储或外部契约，需要分别决策。真实 `tokenUsage`、显式零值和成功后提交缓存状态继续沿用。
- Kiro 配额监控的 provider 和分组聚合要审查约束、汇总状态和中转账号资格。流式响应修复可以独立于此。Composite 路由属于本地明确排除的产品行为。平台配额旧迁移已有本地等价处理，`248` 的应用层校验继续生效。
- 保留直连和中转区分、34 个 API 区域的既有兼容、账号机器 ID 在续期时稳定、Q 到 KRS 的显式开关及本地原生流终态。
