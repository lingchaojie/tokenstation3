## 目标与核心口径

本轮的首要目标是恢复与 Wei-Shaw/sub2api 一致的中转兼容性：删除本地额外加入的 SSE 跨事件身份、顺序、容量和强制终态校验，避免兼容中转已经返回内容却被本地合成 502 或提前中断。

计费口径保持为：

1. 从上游中转返回的 sub2api 兼容 `usage` 提取 token 用量；
2. 按本站模型价格、分组/渠道覆盖、时段/区间价格、倍率、billing mode 和 service tier 计算；
3. 使用本站结果扣款并 exact-once 写入 usage log；
4. 不使用上游 cost/currency 代替本站定价，普通中转计费不估算 token；KIRO direct
   因原生接口不完整返回 input usage，按用户决定保留 nianzs 上游既有的 tokenizer / 请求体
   兜底估算，并继续映射到本站 Anthropic token 价格。

可以默认中转会返回 usage；但若完成的交换确实无法提取可计费用量，该请求标记为上游失败/错误请求，记录请求 ID 与 provider 诊断信息，不允许因缺失 usage 或缺失本站价格而以成功 0 费用落账。管理员以非 nil 价格字段明确配置的 `0` 仍表示免费，不得被误判成缺价或回退到非零默认价。图片、视频、web search 等既有非 token 单位仍按各自语义计费。KIRO credits 保留在用量日志与账号成本统计中；KIRO direct 用户扣费继续使用其既有 token 估算，KIRO relay 必须返回真实 token usage，credits-only 响应不得成功 0 计费。

若 usage 已存在但本站全部计价候选都无法解析，handler 会在 capture/异步扣费提交前同步执行与真实扣费相同的只读计价前缀：不写 usage、余额、配额或 last-used；失败时保留已返回给客户端的真实上游字节，将 capture 标记为 terminal error，并通过 Ops 错误请求通路记录稳定码 `usage_pricing_unavailable`。真实扣款仍由原有有界异步任务执行。未定价公开别名可按既有规则回退到有价格的真实上游模型；所有候选均无价时才 fail closed。

## 转发兼容与 capture

- OpenAI Responses/Chat、Anthropic API-key/兼容路径、Gemini/Antigravity、Bedrock 和 KIRO 共享路径已移除本地额外强校验，保留解析 usage 所需的 JSON/SSE 语法、provider 明确错误、网络/超时/取消、安全 failover 和已提交后 partial-terminal 语义。
- 缺失可计费 usage 的“成功”响应通过统一 finalizer 改为失败，避免再产生成功 0 计费。
- capture 仍是转发的旁路观察者：保留真实最终 provider attempt、脱敏、尺寸/spool 和 terminal-error 策略；capture 不再成为响应接受条件。
- Kimi、Zhipu、DeepSeek 本轮不加入 capture allowlist/录制器，但转发、调度、计费和额度查询可用。
- 保留本地 capture 的“不按单条截断”与 service model allowlist 隔离修复。
