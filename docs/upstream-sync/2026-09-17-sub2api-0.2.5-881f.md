## Independent review and publication

- First independent reviewer: `/root/independent_upstream_review`, verdict
  `NOT SAFE TO PUSH`. It found three issues: API-key filter pagination stopped at
  100 keys, persisted all-NULL quota rows could not be reset in the admin UI,
  and the sample URL allowlist omitted `api.minimax.io`. All three were fixed
  with targeted regressions, followed by the complete frontend, backend
  contract and deployment checks above.
- Second independent reviewer: `/root/final_upstream_review`, verdict
  `NOT SAFE TO PUSH`. It found that `pg_dump` used the migrations advisory lock
  while `psql` restore did not, allowing restore and startup migrations to race
  across instances. Restore now acquires the same session lock before command
  creation, holds it through process completion, and releases or discards the
  connection on all tested exit paths. Full normal, unit and integration suites,
  lint, build, generation consistency and the focused race test passed after
  this fix.
- Third independent reviewer: `/root/final_upstream_review_2`, verdict
  `NOT SAFE TO PUSH`. It confirmed all four earlier fixes and found one stale
