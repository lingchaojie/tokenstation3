## Preserved local invariants

- Direct KIRO and Anthropic-compatible relay accounts remain separate; relay
  accounts with `base_url` continue through the shared gateway.
- Q chat uses body `profileArn`; Q MCP uses
  `x-amzn-kiro-profile-arn`; KRS keeps both with the existing fallback.
- Persisted machine IDs and account-scoped token/cache identity remain stable
  across refresh-token rotation.
- API region and IDC login region are independent as described above.
- Local provider-native capture, redaction, strict terminal validation,
  pre-output failover, committed-partial handling, exact-once usage, KIRO
  credits, and cache presence semantics remain authoritative.
- Cache planning does not mutate tracker state before success. Direct 2xx and
  the first successful WebSearch provider iteration are the commit boundaries;
  failures leave the next identical request as cache creation.
- No production environment, live account, or real upstream provider request
  was used during implementation or verification.

## Review and publication

The first independent full-range review rejected the candidate for four
specific gaps: Chat Completions still used the old mimicry predicate; edit and
reauth could overwrite legacy runtime-region fields; IDC controls did not
expose the 34-region catalog; and KIRO remote compaction had no replay-safe
keepalive. Commit `ec70589fb` addresses all four with focused regression tests.

A new independent full-range review is still required after this archive
update and before any update to shared `dev` or remote branches. Publication
coordinates, remote drift checks, and CI run links must be recorded separately
after that gate; they are not claimed by this archive.
