EasyPay 的确认等待由订单审计记录保留。后续查单暂时失败时，取消和自动过期仍尊重已记录的等待状态。认证后的订单接口显示待确认状态并隐藏付款入口。用户可从订单列表继续追踪指定订单。收银页核对当前账号和订单归属后恢复，其他标签页发起的新订单也能独立查询。付款结果页会放弃账号切换后收到的私人订单响应。

付款结果页从签名链接或 URL 明确提供的旧商户单号查询公开状态。浏览器快照只在核验归属和订单标识后参与币种显示与清理。支付结果所属订单与快照不同，或另一笔订单已替换本地快照时，保留该快照。支付宝确认退款失败后，如果管理员已手工撤销被缩短的原订阅，或手工恢复退款流程撤销的原订阅，保留管理员操作，把退款记为失败并登记人工对账。存在替代订阅时同样保留当前订阅，对账完成前暂停重试。挂起退款会记录它实际撤销订阅的时间。自动恢复只会更新仍是该次撤销的订阅。管理员恢复后再次撤销时，保留新的撤销状态并记录人工对账。

过期任务与已确认付款但缺号的查单各用独立的时间预算。查单任务在一轮内固定订单编号上限，下轮继续逐笔复查，避免慢订单或持续新增订单挡住其他订单。待确认记录写入首次查单的商户标识，查单和结算继续核对该商户，直接比较查单金额和订单金额。SQLite 服务回归和 PostgreSQL 18.1 查询检查覆盖了两类队列与轮转。退款重试在订单事务内归档上一次的同类记录，保留原记录和现有数据库约束。使用历史迁移 093 和 131 的 PostgreSQL 18.1 验证了支付宝、Stripe 重试和迟到查单结果。

Antigravity 兼容流释放失效会话绑定时，会在 Redis 中原子核对当前账号，避免移除其他请求刚写入的绑定。受限 Key 的账户用量权限可查看 Antigravity 的 5 小时和周用量窗口，仅返回已识别的窗口类型、用量比例及重置时间等展示字段。非流式上游中转响应超限时，仍可在向客户端写出错误前切换账号。

OpenAI Messages 保留上游较早帧已报出的用量，空的结束用量不会覆盖已计量的请求。有效的结束快照仍优先，另行上报的托管工具用量与积分一并保留。Kimi、智谱、MiniMax 和 OpenCode Go 返回畸形用量窗口时保留上次有效快照。有效用量和畸形重置时间同时出现时，更新用量并保留上次有效重置时间。确实缺席的窗口照常清理。受限 Key 读取影子账号的模型目录时，也须有实际凭据所在母账号的读取权限。受限目录查询使用独立缓存，查询失败时不会修改账号健康状态或重建 Agent Identity 任务。

原生 Gemini 继续原样返回图片 URI。JSON、SSE 和缓冲响应沿用内联图片计数，内联图片的数据字段须为非空字符串。仅返回 URI 时，已识别或映射到图片模型的请求继续按原有单张规则结算，未识别的自定义别名沿用现有价卡。Messages 兼容接口沿用既有用量口径。

Responses 缓冲的函数调用元数据纳入 8 MiB 保留上限。原生 Responses 从 SSE 转为 JSON 时保留已收到的有效用量，实际有效的最终用量仍优先。

旧版 `/responses/compact` 在选号及刷新账号状态时按实际转发模型检查凭据与上游模型渠道限制。优先采用账号的显式映射，其次使用可用的站点配置模型，保留原有的支持能力检查顺序。原生压缩遇到可重试的模型错误时，会核对备用模型的渠道限制。目标受限时保留原有错误。HTTP 和 WebSocket 的容量降载继续由当前请求重试处理。普通限流和已有模型级规则按原有流程生效。价卡加载保留启动后异步查哈希的方式，退出时取消并等待该后台任务。
